# 工作方法路由

本文件定义本 Skill 自行编写的“怎么做”方法层。它与角色索引无关：角色回答谁负责，方法回答在本任务中采用什么工作方式。

## 类别门禁

以下任务默认不使用产品方法：Bug 或异常排查、部署或发布、生产事故、数据库操作、账号或权限操作。先按对应工程、运维或安全流程处理；只有用户明确要求产品规划产物时，才在不替代主流程的前提下补充一种方法。

## 选择规则

1. 先按任务分类执行类别门禁。
2. 运行 `scripts/search_method_index.py "<用户需求>"`，查看命中的自写方法资料。
3. 选择 0 到 1 个主方法；只有工作阶段不同且职责不重叠时，增加最多 2 个辅助方法。
4. 只读取命中的方法条目和本文件中的对应契约，不加载完整索引到交接提示词。
5. 交接提示词中写成方法契约：方法、适用目的、必须产出、不能替代的判断或授权。

## 方法契约

| 方法族 | 适用目的 | 最低交付 |
|---|---|---|
| 问题定义 | 把模糊想法变成可判断的问题 | 用户、问题、结果、边界 |
| 用户访谈 | 研究真实行为和需求 | 假设、样本、提纲、证据处理 |
| PRD 与验收设计 | 定义要交付的产品行为 | 用户故事、范围、验收条件 |
| 优先级与路线图 | 比较候选投入 | 比较口径、决策、依赖、复盘点 |
| 定价与套餐 | 检验商业包装和价值交换 | 客群、套餐、假设、实验指标 |
| SaaS 指标分析 | 判断产品经营表现 | 指标口径、数据质量、结论边界 |
| 竞品与市场研究 | 认识替代方案和外部证据 | 来源、比较维度、假设与空白 |
| 利益相关者对齐 | 让决策和依赖可追踪 | 决策人、分歧、行动与记录 |
| Agent 协作与上下文管理 | 让多 Agent 执行可交接 | 职责、上下文、接口、升级条件 |

## 负向示例

- “线上数据库迁移失败”：不选择产品方法，先走故障与数据库安全流程。
- “发布新版本到生产”：不选择路线图或 PRD，先明确发布授权、回滚和运行证据。
- “账号无法登录”：不选择用户访谈，先按排错流程收集事实；仅当用户明确要求后续需求研究时，再单独选择方法。
