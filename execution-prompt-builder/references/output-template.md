# 执行提示词交接模板

## 对用户的输出

先给出简短的角色摘要：

```text
角色选择
- 主角色：<名称>，负责 <职责>
- 辅助视角：<名称>，负责 <独立检查面>（可省略）
- 选择依据：<为什么适合本任务>
- 用户调整：<本轮是否修改过角色>
```

然后输出以下两个提示词。使用与用户相同的语言。

## 完整执行提示词

按任务需要保留章节，不要保留空占位符：

```markdown
# 任务

## 专业身份
你以<主角色>身份负责本任务。

- 核心职责：<职责>
- 辅助视角：<可选角色及其独立职责>
- 判断标准：<优先级和取舍原则>
- 角色边界：<不冒充的资格、不负责或无权执行的事项>

## 目标
<一句话说明要实现的结果及其价值>

## 已知背景
- <已确认事实>
- <当前状态>
- <相关用户、系统或业务背景>

## 必须读取或检查的上下文
- `<明确路径或信息源>`：<为什么要读>
- 对可能变化的运行状态先只读查证，不得沿用旧快照。

## 输入与可用资源
- <文件、数据、工具、环境、参考资料>

## 执行范围
- <必须完成的工作>

## 明确不做
- <排除项和禁止扩大范围的事项>

## 权限与安全边界
- <允许的读操作、写操作和外部操作>
- <必须再次获得授权的动作>
- 不在输出、日志、截图或外部平台暴露秘密和敏感信息。

## 工作要求
1. <先调查或理解>
2. <形成方案或实施>
3. <处理异常和边界>
4. <验证>

## 验收标准
- <可观察、可测试、可计算或可举证的完成条件>

## 验证证据
- <必须运行的测试、查询或检查>
- 分开报告“未执行”“执行失败”“验证通过”，不能把推测写成事实。

## 最终交付
- <文件、报告、代码或操作结果>
- 用<语言和格式>简洁汇报：做了什么、证据是什么、还有什么风险或待办。

## 待执行 Agent 查证
- <无需继续询问用户、但执行前必须查明的事实>

## 当前假设
- <低风险且已经明确标注的假设；没有则删除本节>
```

## 精简执行提示词

精简版仍必须保留目标、角色、范围、权限、验收和验证，不能只剩一句命令：

```text
以<主角色>负责<目标>。先读取/检查<关键上下文>，只在<范围>内行动，不做<非目标>，并遵守<权限边界>。完成标准是<验收标准>。必须用<测试或证据>验证，最后按<交付格式>报告结果、未验证事项和剩余风险。
```

## 交付后说明

最后列出“执行 Agent 仍需查证的事项”。没有时明确写“无”。不要把新的澄清问题藏在提示词末尾；真正阻塞的问题必须在生成提示词前询问用户。
